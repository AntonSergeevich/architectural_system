# 04. Система: что строим

Три контура, один код:

| Контур | Для кого | Задача |
|---|---|---|
| **Публичный сайт** | посетитель | Объяснить, отфильтровать, посчитать, привести заявку |
| **Кабинет заказчика** | клиент в работе | Видеть этап, оставлять правки, согласовывать, понимать договор |
| **Кабинет Дарьи** | Дарья | Воронка, проекты, деньги, прайс, портфолио |

---

## Модель данных

Не финальная схема, а состав сущностей и то, зачем каждая нужна.

### Каталог и цены

```
ServiceModule       код, название, блок (A/Б/В), единица (м²/этап/выезд/фикс),
                    цена, обязательный ли, порядок, описание,
                    текст плашки «что вы берёте на себя», активен ли
ModuleGroup         группа взаимоисключающих модулей (три уровня A6)
Preset              название, набор модулей, порядок, «по умолчанию»
PriceHistory        модуль, цена, дата — чтобы старые КП не переписывались
ComplexityFactor    характер интерьера → коэффициент
```

Один каталог питает конструктор, КП, состав договора и чек-листы этапов.
Дублировать состав услуг где-то ещё нельзя — разъедется.

### Клиенты и заявки

```
Client              имя, телефон, почта, мессенджер, источник, заметки Дарьи
Property            объект: город, адрес, тип (новостройка/вторичка/дом),
                    площадь по документам, площадь по обмеру, комнат,
                    ключи получены, желаемый срок заезда, свои строители
Lead                клиент, объект, источник, статус, следующий шаг,
                    дата следующего шага, история касаний
LeadAnswer          ответы квалификационной анкеты
```

**`Lead.next_action_at` — обязательное поле.** Заявка без даты следующего
шага — это и есть потерянная заявка. Всё, что просрочено, светится
на дашборде.

### КП

```
Quote               клиент, объект, площадь, коэффициент, набор позиций,
                    итог по блокам, срок действия, публичная ссылка,
                    статус (черновик/отправлено/открыто/принято/просрочено)
QuoteItem           модуль, цена на момент выставления, количество, сумма
QuoteView           когда открывали — сигнал «пора звонить»
```

Цены копируются в `QuoteItem` при выставлении. Изменение прайса не должно
задним числом менять отправленное клиенту.

### Проект

```
Project             клиент, объект, пресет, состав модулей, договор,
                    дата старта, текущий этап, статус, WIP-флаг
Stage               проект, номер, название, статус, план/факт дат,
                    нормативная длительность, кто ждёт (Дарья/клиент)
StageChecklist      пункты этапа: что сделано
Approval            согласование этапа клиентом: кто, когда, чем
Revision            правка: этап, помещение, автор, текст, статус, ответ
ProjectFile         файлы этапа: планировки, коллажи, визуализации, чертежи
Note                заметки Дарьи по проекту и по этапу — приватные
```

**`Stage.waiting_on`** — небольшое поле с большим смыслом. Оно разделяет
«я не успела» и «жду ответа клиента», и именно из него собирается честная
строка «ваши согласования: NN дней».

### Договоры

```
ContractTemplate    вид (проектирование/надзор/комплектация), версия, текст
ContractClause      пункт: номер, текст юридический,
                    расшифровка по-человечески, важный ли
Contract            проект, шаблон, реквизиты, суммы, дата, статус
ClauseQuestion      клиент отметил пункт как непонятный + ответ Дарьи
ContractAck         подтверждение, что клиент прочитал и понял
```

### Комплектация и надзор

```
ProcurementStage    этап комплектации по плану работ, бюджет, статус
ProcurementItem     позиция: что, артикул, поставщик, КП, срок поставки,
                    цена, запас, статус (подобрано → … → принято)
SupplierQuote       КП поставщика для сравнения: срок / цена / качество
SupervisionVisit    выезд: дата, план/факт длительности, отчёт, фото,
                    замечания по соответствию проекту
```

### Публичное

```
PortfolioProject    объект: заголовок, площадь, стиль, город, год,
                    описание, состав выполненных работ, опубликован ли
PortfolioPhoto      фото, порядок, до/после
PortfolioClient     что о клиенте показывать (фото, цитата) — по согласию
Testimonial         отзыв
Article             материал блога / лид-магнит
Referral            кто кого привёл, какой бонус, статус
SiteSettings        контакты, реквизиты, тексты, фото Дарьи
```

`PortfolioClient` — по прямой просьбе Дарьи выводить информацию о клиенте
в портфолио. Обязательно с флагом согласия: чужое лицо и чужая квартира
публикуются только явным разрешением.

## Публичный сайт

|---|---|

| **Обо мне** | Тот самый фильтр «свой / не свой». Личность, ценности, подход |
| **Услуги** | Модули по блокам с раскрытием: что входит, что не входит |
| **Конструктор** | Ядро сайта, см. ниже |
| **Портфолио** | Объекты. Не только картинки — что было сделано и почему так |
| **Кейс** | Один объект целиком: задача → решение → результат |
| **Как я работаю** | 8 этапов, регламент общения, сроки |
| **Вопросы и возражения** | «Почему не дешевле», «а что такое авторский надзор», «а нам нейросеть нарисует» |
| **Контакты и заявка** | Форма с квалификационной анкетой |
| **Полезное** | Лид-магниты и материалы для тех, у кого ремонт не завтра |

### Конструктор — центральный экран

Клиент **собирает комнату из блоков**: перетаскивает блоки услуг
в изометрическую комнату, комната обрастает частями, цена пересчитывается. Полная спецификация — в отдельном
документе [07-конструктор.md](07-конструктор.md), включая механику
перетаскивания на телефоне.

Коротко:

1. Клиент вводит **площадь и количество помещений**.
2. Отвечает на вопрос **о характере интерьера** — это коэффициент.
3. Видит **фундамент** — обязательные модули, они уже уложены.
4. Перетаскивает блоки со склада на дом. Цена **пересчитывается мгновенно**.
5. Незаложенный блок оставляет в доме **видимую дыру** — вместо плашки
   «что вы берёте на себя» человек буквально видит дом без крыши.
6. Каждый блок **раскрывается**: что входит, сколько занимает, что на выходе.
7. Итог тремя строками: проектирование, надзор, комплектация.
8. Кнопка **«получить это предложение»** → заявка с готовым составом.

Ключевое: **отдельная ссылка на каждый собранный расчёт**. Именно это
заменяет PDF, который Дарья собиралась делать: одна ссылка, всё внутри,
открывается на телефоне, всегда актуальна.

## Кабинет заказчика

Отвечает на вопрос, с которого начинается тревога: **что происходит
с моим проектом прямо сейчас.**

| Экран | Содержание |
|---|---|
| **Мой проект** | Таймлайн 8 этапов: пройденные, текущий, будущие. У текущего — что делается, что ждёт от клиента, ориентировочный срок |
| **Материалы** | Файлы по этапам: планировки, коллажи, подборки, визуализации, чертежи, альбом |
| **Правки** | Оставить правку по помещению и этапу. История со статусами |
| **Согласования** | Что нужно утвердить. Одна кнопка — и этап двигается |
| **Договор** | Текст с подсветкой важного, расшифровки по клику, отметки «есть вопрос» |
| **Оплаты** | Что оплачено, что предстоит, по этапам |
| **Комплектация** | Позиции и их статусы — если модуль подключён |

Правило: **клиент не должен писать в мессенджер, чтобы узнать статус.**
Каждый такой вопрос — это дефект интерфейса, а не назойливость клиента.

## Кабинет Дарьи

| Экран | Содержание |
|---|---|
| **Дашборд** | Просроченные касания по заявкам · этапы, где ждут её · этапы, где ждут клиента · открытые правки · выезды на неделю · загрузка (WIP) |
| **Воронка** | Канбан заявок с перетаскиванием: новая → квалифицирована → созвон → КП отправлено → договор → в работе. Отказы с причиной |
| **Проекты** | Канбан проектов по этапам — тот самый drag-n-drop, который просила Дарья. Карточка тянется из этапа в этап |
| **Карточка клиента** | Всё в одном месте: контакты, объект, история касаний, КП, договоры, проект, правки, оплаты, приватные заметки |
| **Календарь** | Выезды, обмеры, созвоны, брифы |
| **Прайс** | Модули, цены, коэффициенты. Меняется здесь, применяется везде |
| **КП** | Собрать, отправить, увидеть «открыто» |
| **Портфолио** | Публикация объектов, фото, тексты |
| **Настройки** | Контакты, реквизиты, шаблоны договоров, нормативы длительности этапов |

**Заметки на каждом этапе** — прямая просьба Дарьи. Приватные, видит
только она: чем этот клиент отличается, что ему нельзя предлагать, о чём
он просил на созвоне полгода назад.

## Что автоматизируется — и что нет

### Автоматизируем

| Что | Как |
|---|---|
| Расчёт стоимости | Конструктор по каталогу и коэффициентам |
| Формирование КП | Из состава конструктора, одной ссылкой |
| Формирование договора | Из шаблона, реквизитов и состава модулей — Дарья просила |
| Напоминания о касаниях | Просроченный `next_action_at` — на дашборд и в уведомление |
| Уведомления клиенту | Этап сдан, нужно согласование, правка выполнена |
| Уведомления Дарье | Новая заявка, КП открыто, новая правка, согласование получено |
| Чек-листы этапов | Генерируются из состава модулей проекта |
| Сроки | Считаются из нормативов, состава и очереди |
| Портфолио из проекта | Завершённый проект превращается в публикацию в пару кликов |

### Не автоматизируем — сознательно

- **Первичный созвон.** Это то, ради чего к Дарье приходят. Никаких
  чат-ботов на входе.
- **Подбор решений.** Это и есть работа.
- **Ответы на правки.** Шаблонный ответ на живую правку хуже, чем никакого.
- **Онлайн-оплата на старте.** Дарья — самозанятая, чеки через «Мой налог».
  Поля под эквайринг закладываем, подключение — когда появится потребность.

## Уведомления

Один принцип: **запрос никогда не ходит в SMTP или Telegram напрямую.**
Он кладёт запись в очередь, очередь разбирает фоновая задача. Упавшая
почта не может сломать согласование этапа.

Каналы: почта, Telegram, лента в кабинете. У каждого уведомления —
ключ дедупликации, чтобы повторный запуск планировщика ничего не задвоил.

## Роли

```
Дарья    — полный доступ
Клиент   — только свой проект: этапы, файлы, правки, договор, оплаты
Гость    — публичный сайт и конструктор
```

Третьей роли (ассистент, визуализатор) пока нет, но модель прав пишется
так, чтобы её можно было добавить: 3D-визуализатор работает по техзаданию
Дарьи, и однажды ему понадобится доступ к своему куску проекта.

## Что делает эту систему рабочей

Три вещи, без которых остальное — просто красивый сайт.

1. **Один каталог услуг.** Конструктор, КП, договор и чек-листы берут
   состав из одного места. Разные списки в разных местах — это возврат
   к «объясняю каждый раз с нуля», только теперь ещё и с расхождениями.

2. **Ни одной заявки без даты следующего шага.** Это техническое решение
   боли №1. Не «напоминалка», а невозможность оставить заявку без
   следующего действия.

3. **Правки только в системе.** Как только правки снова начинают приходить
   в мессенджер, всё остальное разваливается: этапы не закрываются,
   согласований нет, юридическая защита исчезает. Это должно быть
   зафиксировано в договоре и в регламенте, а не только в интерфейсе.
