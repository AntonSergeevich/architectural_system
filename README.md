# Система для архитектора-дизайнера

Сайт и рабочая система Дарьи — проектирование интерьеров, авторский надзор,
комплектация. Красноярск и удалённая работа.

Проект решает не «сделать красивый сайт», а три конкретные проблемы:
клиент не понимает, за что платит; заявки и правки живут в мессенджерах
и теряются; всё держится на одном человеке, у которого нет ни шаблона
разговора, ни границ.

## Ключевое решение всего проекта

**У Дарьи не три тарифа, а комбинаторика.** Клиент отказывается то от
чертежей (в семье свой строитель), то от фотореалистичного 3D (уверен
в своём пространственном воображении), то просит частичный комплект листов.
Фиксированные пакеты это не описывают — при попытке их натянуть каждый
второй разговор превращается в индивидуальный пересчёт голосом.

Поэтому в основе — **каталог модулей** с ценой и единицей измерения,
поверх которого лежат **пресеты** (те самые «Технический / Наглядный /
Полный / Под ключ»). Пресет — это просто заранее отмеченные галочки
в конструкторе, а не отдельная сущность.

Из этого следует всё остальное: конструктор КП на сайте, автоматический
расчёт стоимости и срока, состав договора, чек-листы этапов в кабинете.
Один каталог — один источник правды.

## Статус

Стадия: **структура и ТЗ**. Кода пока нет — сначала фиксируем бизнес-логику,
потом пишем. Что нужно получить от Дарьи, чтобы двигаться дальше, собрано
в конце [docs/06-карта.md](docs/06-карта.md).

## Планируемый стек

Django 5.2 LTS + PostgreSQL, серверный рендеринг, интерактив на ванильном JS
поверх `fetch`, дизайн-система на CSS-токенах. Без сборки фронтенда: проект
живёт годами и должен собираться командой `pip install -r requirements.txt`
и через пять лет тоже.
