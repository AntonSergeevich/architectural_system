# Система для архитектора-дизайнера

Сайт и рабочая система Дарьи — проектирование интерьеров, авторский надзор,
комплектация. Красноярск и удалённая работа.

Проект решает не «сделать красивый сайт», а три конкретные проблемы:
клиент не понимает, за что платит; заявки и правки живут в мессенджерах
и теряются; всё держится на одном человеке, у которого нет ни шаблона
разговора, ни границ.

Django 5.2 LTS + PostgreSQL, серверный рендеринг, без сборки фронтенда.
Интерактив — на ванильном JS поверх `fetch`; при выключенном JavaScript
формы продолжают работать обычным POST, включая расчёт стоимости.

## Быстрый старт

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env          # локально можно не заполнять: будет SQLite
python manage.py migrate
python manage.py seed_catalog        # каталог услуг, цены, пресеты, этапы
python manage.py seed_legal          # документы и шаблоны договоров
python manage.py createsuperuser     # это Дарья
python manage.py runserver
```

Тесты:

```bash
python manage.py test apps
```

## Ключевые решения

**У Дарьи не три тарифа, а комбинаторика.** Заказчик отказывается то
от чертежей (в семье свой строитель), то от фотореалистичного 3D (уверен
в своём пространственном воображении), то просит частичный комплект листов.
Фиксированные пакеты этого не описывают. Поэтому в основе — **каталог
модулей**, а «тарифы» — это пресеты, то есть заранее отмеченные галочки.
Из одного каталога питаются конструктор, КП, договор и чек-листы этапов.

**Конструктор — дом из кубиков.** Метафора работает вместо текста: снятый
модуль оставляет в доме видимую дыру. Дом без крыши объясняет ценность
авторского надзора лучше любой плашки — и снимает с Дарьи разговор, который
ей «влом» вести голосом. Стартовое состояние — собранный дом «Под ключ»:
заказчик не собирает с нуля, он разбирает.

**Расчёт считает один и тот же код.** И на сайте, и при выставлении КП.
Двух реализаций быть не должно: расхождение между «посчитал сайт»
и «выставила Дарья» — ровно тот разговор, от которого система избавляет.

**Заявка не может остаться без следующего шага.** `Lead.next_action_at` —
обязательное поле, просроченные светятся в кабинете и уходят напоминанием
по cron. Это техническое решение боли «заявки теряются».

**Правки живут в системе, а не в мессенджере.** Тогда их не нужно
переписывать второй раз ради договора, объём виден обоим, а история
согласований существует и защищает.

**Срок ответа считается в рабочих часах.** Регламент Дарьи — «отвечу
в течение суток в рабочее время». Вопрос в пятницу вечером получает срок
до понедельника вечера, и заказчик видит это сразу при отправке. Система
никогда не обещает быстрее регламента, даже если фактически Дарья отвечает
за час.

**Цены живут в базе, а не в вёрстке.** Поднять цены — поменять числа
в кабинете. Уже выставленные КП при этом не меняются: цена копируется
в позицию в момент выставления.

**Приём оплат выключается сам, если не настроен.** Пока реквизитов
GetPlatinum нет, кнопка не показывается, а счёт отмечается оплаченным
вручную. Кнопка, ведущая в никуда, хуже её отсутствия.
